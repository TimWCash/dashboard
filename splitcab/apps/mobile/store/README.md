# Store submission

Everything for the App Store and Google Play lives here. The full sequence of accounts and steps is in [`docs/launch-checklist.md`](../../../docs/launch-checklist.md).

| What | Where |
|---|---|
| App Store listing, age rating, review notes | [`../store.config.js`](../store.config.js), pushed with `npx eas-cli@latest metadata:push` |
| Google Play listing and policy answers | [`google-play/listing.md`](google-play/listing.md) |
| App Privacy / Data safety answers | [`privacy-answers.md`](privacy-answers.md) |
| App icon, adaptive icon, splash, notification icon | `../assets/`, generated by [`brand/generate-assets.mjs`](brand/generate-assets.mjs) |
| Play icon and feature graphic | `google-play/` |
| Screenshots (iPhone 6.7" 1290×2796, Android 1080×1920) | `screenshots/ios`, `screenshots/android`, built by [`screenshots/compose.mjs`](screenshots/compose.mjs) |

## Build and submit

```bash
cd apps/mobile
npx eas-cli@latest init                                   # once: links the project, gives you EAS_PROJECT_ID
npx eas-cli@latest build --platform all --profile production
npx eas-cli@latest submit --platform ios --profile production
npx eas-cli@latest submit --platform android --profile production
npx eas-cli@latest metadata:push                          # App Store text, screenshots, age rating, review notes
```

Set these as EAS environment variables (production) before building: `EXPO_PUBLIC_API_URL`, `EAS_PROJECT_ID`, `APP_BUNDLE_ID` (if not `ie.splitcab.app`), and optionally `APPLE_PAY_MERCHANT_ID`, `EXPO_PUBLIC_UBER_CLIENT_ID`, `EXPO_PUBLIC_FREENOW_URL`. For `metadata:push`, set `REVIEW_PHONE`, `REVIEW_CODE` and the `REVIEW_CONTACT_*` values in your shell; they must match the API's `REVIEW_PHONE` and `REVIEW_CODE`.

## Regenerating assets

```bash
node store/brand/generate-assets.mjs           # icons, splash, Play graphics (needs Playwright + Chromium)
node store/screenshots/compose.mjs <captures>  # captioned screenshots from 1170×2532 app captures
```

Captures are the app at 390×844 points and 3x scale with demo data: welcome, plan, match proposal, confirmed ride and completed ride (file names are listed in `compose.mjs`). Retake them whenever the UI changes.
